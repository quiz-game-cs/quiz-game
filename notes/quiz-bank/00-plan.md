# 문제은행 생산 계획 — 100세트 × 50문제 = 5,000문제

## 확정 사항

- **규모**: 100세트 전량. 답은 5,000문제 **전체에서 유일** (세트 간 중복 불허).
- **산출물**: 마크다운. `notes/quiz-bank/set-001.md` ~ `set-100.md`.
- **세트 구성**: `docs/writing-guidelines.md` 세트 체크리스트 그대로.
  - 장르: DB 카테고리 체계(`src/db/category-data.ts`)가 유일 기준. 골고루 — 대분류당 5문제 안팎이 기본값이며 강제 아님 (가이드 §5.3).
  - 문제마다 소분류 코드(`- cat:`)와 난이도를 부여 — DB `categoryId`·`difficulty`로 임포트 (가이드 §5).
  - 단문(단서 1~2개) 위주. 3층 장문은 세트당 10~15문제. 긴 문제 뒤엔 짧은 문제.
  - 병렬·열거·인용·정식명칭 리드 세트당 5문제 내외.
- **난이도 배분** (세트당 권장): 기본 35 / 관심 12~13 / 마이너 2~3 (= 70/25/5).

## 난이도 조작적 정의 (기준 원본은 가이드 §5.2 — 여기는 요약)

| 등급 | 세트 내 비중 | 정의 (답 기준) | 앵커 예 |
|---|---|---|---|
| 기본 | 70% (35문) | 답을 들으면 성인 90% 이상이 안다. 교육과정 필수 + 일상 사물·상식 | 세종대왕, 피아노, 광합성, 삼일절 |
| 관심 | 25% (12~13문) | 그 분야에 가벼운 관심이 있으면 아는 답 (인지도 40~70%) | 가우디, 쇼팽 야상곡, 오프사이드, 미장센 |
| 마이너 | 5% (2~3문) | 애호가 수준 (인지도 40% 미만). **단, 문제문 자체가 흥미로운 사실이어서 모르는 사람도 "음~ 그렇구나" 해야 함** | 캉디드, 판테온의 오쿨루스, 데우스 엑스 마키나 |

마이너 문제 필수 조건: 답을 모르는 청자에게도 문제문이 하나의 재미있는 트리비아로 성립할 것.
(예: "'신은 죽었다'라고 쓴 철학자가 정작 말년에 ○○했다는…" 식으로 도입부가 이야기가 되는 문제)

## 한국 청자 치환 규칙

일본 문제은행 스타일을 참고하되, 일본 국내 한정 소재는 다음처럼 치환한다.

| 일본 은행의 소재 | 한국 청자용 치환 |
|---|---|
| 일본 지리·지명 유래 (예: 兜町) | 한국 지리·지명 유래 (예: 말죽거리, 여의도) |
| 한자 읽기(難読漢字) 문제 | 우리말 맞춤법·순우리말·사자성어 |
| 일본 연예인·방송 | 한국 가요·드라마·예능 (+ 세계적으로 소비되는 것) |
| 일본 국내 스포츠(스모 등) | 한국 전통(씨름)·국내 리그, 글로벌 스포츠 |
| 일본 세시풍속 | 한국 세시풍속(단오, 정월대보름 등) |
| 세계 공통 소재(과학·세계사·클래식 등) | 그대로 사용 |
| 일본 서브컬처 | 한국에서 널리 소비된 작품만 (은하철도999 O, 국내 미방영 마이너 작품 X) |

## 전역 유일성 관리

**중복의 정의**: 같은 대상을 가리키는 답이 다시 나오면 중복이다. **표기가 같아도 가리키는 대상이 다르면 중복이 아니다** (예: 피아노[악기]와 피아노[셈여림말]). 기존 inseop 53문제의 답과도 같은 기준으로 중복을 금지한다.

**메커니즘 — 세트 파일 전수 스캔** (로컬 순차 생산 체제):

1. 세트 작성 전, `set-*.md` 전 대역 + `src/db/polished-data.ts` + DB 전용 5답(AGENT-BRIEF 참조)의 답을 수집해 금지 목록을 만든다.
2. 세트 완성 후 같은 목록과 대조한 결과를 "## 세트 점검"에 기록한다 (정규화: 공백·대소문자·기호 제거).

(구 설계였던 장르별 답 풀 사전 구축·배정 방식은 병렬 대량 생산용이었으므로 폐기. `pool-02-과학.md`는 의무 아닌 **소재 아이디어 뱅크**로만 남긴다 — 답을 풀에서 꺼낼 필요도, 배정 표시를 할 필요도 없다.)

## 생산 파이프라인 (로컬 순차)

1. 세트 작성: 금지 목록(전수 스캔)을 만든 뒤 장르당 5문제(기본 3~4, 관심 1~2, 마이너 0~1)를 작성.
2. 세트 체크리스트 점검 (길이 리듬·형태 다양성·8할 기본).
3. 10세트마다 중복 검사 스크립트 실행.
4. 윤문 완료(status: 윤문완료/확정)된 세트만 DB 임포트.
