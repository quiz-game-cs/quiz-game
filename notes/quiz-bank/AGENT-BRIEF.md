# 문제 생성 에이전트 공용 브리핑

이 문서는 사람·자동화 에이전트(데일리 루틴, Codex 등)가 문제 세트를 만들 때 따라야 할 단일 기준이다.
**이 문서만 읽고 시작하지 말 것 — 아래 3개 문서를 먼저 정독한다.**

## 필독 문서 (순서대로)

1. `docs/writing-guidelines.md` — 문제 작성·윤문 가이드 전체 (부호, 어미, 답 규칙, 정보 배치, 세트 구성)
2. `notes/quiz-bank/00-plan.md` — 난이도 조작적 정의(기본/관심/마이너), 한국 청자 치환 규칙, 유일성 규칙
3. `notes/quiz-bank/set-001.md` — **품질 기준선.** 문체·형식의 수준을 참고하되, 단서 배치가 최신 `writing-guidelines.md`와 충돌하면 가이드를 우선한다

## 세트 규격 (요약 — 상세는 필독 문서, 특히 가이드 §5)

- 1세트 = 50문제. 장르는 DB 카테고리 체계(`src/db/category-data.ts`) 기준으로 골고루 — 대분류당 5문제 안팎이 기본값(강제 아님)
- 난이도: 기본 35 / 관심 12 / 마이너 3 안팎 (가이드 §5.2의 정의 = DB difficulty 1/2/3)
- 형태: 단문 위주, 3층 장문 10~15개(연속 금지), 병렬·열거·인용/정식명칭 합쳐 5개 내외. **수치를 맞추려고 불필요한 단서나 성립하지 않는 형식을 추가하지 말 것**
- 파일 형식: set-001.md와 완전히 동일 — 프런트매터, `N. [난이도](형태) 문제문`, `- A: 답1 / 답2`, **`- cat: 소분류코드 이름`** (예: `- cat: 0104 문학·세계문학`). **파서가 읽으므로 구조 변형 금지**

## 품질 필수 조건

- 문제문은 사실의 목록이 아니라 **처음 듣는 순간부터 구조가 해석되는 한 문장**이어야 한다. 범주어·`등`·연결어·종결 표현은 청자가 아직 문장을 끝까지 듣지 않은 상태에서도 정보의 역할과 답의 종류를 파악하게 하는 실시간 안내 표지다
- 아래 규칙은 단어를 기계적으로 삽입하는 서식이 아니다. 부분 수정으로 범주어·연결어를 넣은 뒤에는 문장 전체를 다시 읽고, 더 어색해졌다면 빼거나 전체 구조를 다시 짤 것
- 훅은 정답을 좁히거나 그 자체로 들을 가치가 있을 때만 사용. **단지 마이너하다는 이유로 희귀 사실을 앞에 끼워 넣지 말 것**
- 작품 문제는 작자·연도·갈래·문학사적 위치 같은 메타 정보가 자연스럽게 틀을 잡아 주면 내용보다 먼저 배치하되, 상징적인 첫 장면이 더 좋은 리드라면 내용으로 바로 시작
- 고유명사의 정체가 불분명할 때는 `저서·소설·영화·오페라·피아노곡·민요` 같은 범주어를 붙이되, `〈시인〉이라는 제목`, `'무모한 도전'이라는 이름`처럼 문맥이 이미 역할을 밝히면 중복하지 말 것
- 작품·업적의 일부만 나열하면 `등`을 붙이고, 전부를 열거하면 `4대 비극으로 이루어진`처럼 완결된 묶음임을 밝힐 것
- 줄거리로 작품을 물을 때는 `○○가 쓴, ~하는 내용의 소설` 또는 `~하는 내용을 그린 ○○의 소설`처럼 수식어와 질문 대상을 자연스럽게 연결할 것
- 각 서술어의 주어와 소유 관계를 확인할 것. 누구의 작품인지 떠 있는 `작품을 K와 번호로 표기하며`보다 `그의 작품은 K와 번호로 표기되며`처럼 관계가 분명한 문장을 쓸 것
- 긴 속담·관용구는 핵심 빈칸만 물어 입력 부담을 줄이되, 핵심 낱말과 완전한 표현을 모두 정답으로 인정할 것
- 작품·사물은 `무엇일까요?`, 용어·기법·현상의 명칭은 `무엇이라고 할까요?`처럼 답의 종류에 맞는 종결 표현을 사용할 것
- 문제 앞부분이 최종 정답보다 더 자연스러운 다른 답을 가리키면 소재·정답·정보 순서를 다시 설계
- 둘 다 성립하는 단서 순서는 절대 규칙보다 문장 호흡과 확정 흐름에 따라 고를 것. 한 문항의 취향 피드백을 `행정 주소는 항상 뒤` 같은 보편 규칙으로 확대하지 말고 그 선택의 이유를 적용할 것
- 병렬·열거는 형식 수를 채우려고 만들지 말 것. 병렬은 같은 대비 축을 유지하는 데서 그치지 않고 앞절의 유난히 구체적인 범위 한정이나 표현이 뒷절의 방향을 예고해 먼저 누를 여지를 주어야 하며, 열거는 처음부터 끝까지 같은 묶음을 유지해야 한다
- 용어 문제는 유래 + 현재 용법을 함께
- 마이너 문제는 모르는 사람도 "음~ 그렇구나" 할 훅이 문제문에 있어야 하며 `- 훅:` 메모로 명기
- **인용구 창작 절대 금지** — 원문이 확실한 인용만. 불확실한 사실은 "~로 알려져 있다"로 헤지하거나 소재 교체
- 시간이 지나면 낡는 사실에는 연도 명시
- 어미 "~일까요?" 계열, 자연스러운 한국어 관형 연결(`~하는 내용의 소설`, `~하는 내용을 그린 소설` 등)

## 중복 규칙 (전역 유일성)

- 시작 전에 `notes/quiz-bank/set-*.md` 전체 + `src/db/polished-data.ts`의 모든 답을 수집해 금지 목록을 만든다
- 추가로 다음 5개 답은 DB에만 존재하므로(파일에 없음) 금지 목록에 반드시 포함: **카노사의 굴욕, 마들렌, 우라늄, 에클레르, 카멜레온**
- 비교는 공백·대소문자·기호 제거 정규화 기준
- 예외: 표기가 같아도 가리키는 대상이 다르면 중복 아님 (예: 피아노[악기] vs 피아노[셈여림말])
- 세트 말미에 "## 세트 점검" 블록으로 중복 검사 결과를 기록
